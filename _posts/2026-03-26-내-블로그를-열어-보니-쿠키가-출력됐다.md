## 시작하며

<br>

어느 날 예전에 작성한 bWAPP 실습 포스트를 다시 열어봤다가 갑자기 alert 창이 하나 떴습니다.

<br>

내용은 제 Google 계정 쿠키였습니다.

<br>

내 블로그 페이지에서 쿠키가 노출된 걸까요?

<br>

## 무슨 일이 있었나

<br>

bWAPP XSS 실습 글을 작성할 당시, 실제로 삽입했던 페이로드를 설명하면서 이렇게 적었습니다.

<br>

```html
<script>alert(document.cookie)</script>
```

<br>

문제는 이걸 코드 블록 안에 넣지 않고 **평문으로 그냥 적었다**는 것입니다.

<br>

마크다운 문서에서 백틱(`) 없이 `<script>` 태그를 그냥 쓰면, Jekyll은 이를 HTML 태그 그대로 페이지에 삽입합니다. 그리고 브라우저는 당연히 그걸 스크립트로 실행합니다.

<br>

결과적으로 제 블로그 포스트를 방문하는 모든 사람의 브라우저에서 `document.cookie`가 alert로 출력됐습니다. 제가 직접 들어갔을 때 뜬 건 제 Google 쿠키였습니다.

<br>

## 왜 이런 일이 생기나

<br>

마크다운은 기본적으로 HTML을 허용합니다. Jekyll도 마찬가지로 마크다운 파일 안에 작성된 HTML 태그를 그대로 렌더링합니다.

<br>

코드 블록(` ``` `)으로 감싼 경우나 인라인 백틱(`` ` ``)으로 감싼 경우에는 내부 내용이 HTML 엔티티로 이스케이프 처리됩니다.

<br>

- `<` → `&lt;`
- `>` → `&gt;`

<br>

그래서 브라우저는 이를 실행 가능한 태그가 아닌, 화면에 표시할 텍스트로 인식합니다.

<br>

반면 코드 블록 없이 평문으로 작성하면 그대로 HTML로 파싱되어 실행됩니다.

<br>

| 작성 방식 | 렌더링 결과 |
|-----------|------------|
| 평문 `<script>...</script>` | 스크립트로 실행됨 |
| 코드 블록 안에 작성 | 텍스트로 표시됨 |

<br>

## 해결 방법

<br>

간단합니다. 코드 예시는 반드시 코드 블록 안에 넣습니다.

<br>

````markdown
```html
<script>alert(document.cookie)</script>
```
````

<br>

언어 지정자(`html`, `javascript` 등)를 붙여주면 신택스 하이라이팅도 적용됩니다.

<br>

Jekyll이 마크다운을 HTML로 변환할 때, 문서 안에 직접 쓴 HTML 태그도 그대로 통과시키도록 설계되어 있습니다. 이를 설정 하나로 막기는 어렵기 때문에, 결국 가장 확실한 방법은 코드 예시를 반드시 코드 블록 안에 넣는 습관을 들이는 것입니다.

<br>

## 마치며

<br>

bWAPP에서 XSS를 실습하고 글을 쓰다가, 제 블로그에 XSS 취약점을 사용한 아이러니한 상황이었습니다.

<br>

<br>
