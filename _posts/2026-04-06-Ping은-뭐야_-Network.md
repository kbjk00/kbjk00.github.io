## 시작하며

네트워크 연결이 제대로 되는지 확인하고 싶을 때 가장 먼저 떠오르는 명령어가 바로 `ping`이다. 이 글에서는 ping이 무엇인지, 어떤 원리로 동작하는지, 그리고 실행 결과를 어떻게 읽는지를 다룬다. 이 글을 읽으면 ping 명령어를 직접 실행하고 그 결과를 해석할 수 있다.

## ping이란

ping은 특정 기기나 서버가 네트워크 상에서 응답하는지 확인하고, 응답까지 걸리는 시간을 측정하는 네트워크 진단 도구다. Linux와 Windows 모두에 기본으로 설치되어 있어 별도 설치 없이 바로 사용할 수 있다.

## ICMP란

ping은 **ICMP(Internet Control Message Protocol, 인터넷 제어 메시지 프로토콜)** 를 사용한다. ICMP는 우리가 흔히 알고 있는 TCP나 UDP와는 다른 프로토콜로, 데이터를 전송하는 용도가 아니라 네트워크 상태를 진단하고 오류를 알리기 위한 제어 전용 프로토콜이다.

## 동작 원리 — 에코와 에코 응답

ping의 동작 방식은 매우 단순하다.

1. 출발지 기기가 대상 기기로 **ICMP 에코(echo)** 패킷을 보낸다.
2. 대상 기기가 이를 받으면 **ICMP 에코 응답(echo reply)** 패킷을 돌려보낸다.
3. 출발지 기기는 패킷을 보낸 시점과 응답을 받은 시점의 차이를 계산하여 응답 시간을 구한다.

이 과정이 지정한 횟수만큼 반복되며, 최종적으로 전송한 패킷 수, 수신한 패킷 수, 평균 응답 시간이 출력된다.

## 기본 사용법

```bash
ping <IP주소 또는 도메인>
```

이 명령어는 지정한 대상에 ICMP 에코 패킷을 반복적으로 전송한다.

예시:

```bash
ping 8.8.8.8
```

이 명령어는 구글의 공개 DNS 서버(`8.8.8.8`)에 ping을 보낸다. 해당 서버가 응답 가능한 상태라면 에코 응답이 돌아온다.

도메인 주소도 사용할 수 있다:

```bash
ping google.com
```

이 명령어는 `google.com`에 해당하는 서버로 ping을 보낸다. 내부적으로 도메인 이름이 IP 주소로 변환(DNS 조회)된 뒤 ICMP 패킷이 전송된다.

## Windows와 Linux의 차이

ping 명령어는 OS에 따라 기본 동작이 다르다.

| | Windows | Linux |
|---|---|---|
| 기본 전송 횟수 | 4번 후 자동 종료 | 무한 반복 (`Ctrl+C`로 중단) |
| 횟수 지정 옵션 | `-n` | `-c` |

예를 들어 Linux에서 4번만 보내고 싶으면 `ping -c 4 8.8.8.8`처럼 사용한다.

## TTL로 OS 추측하기

`ttl` 값은 패킷이 거쳐갈 수 있는 최대 홉 수로, OS마다 기본값이 다르다.

| OS | 기본 TTL |
|---|---|
| Linux | 64 |
| Windows | 128 |
| macOS | 64 |

응답 패킷의 TTL을 보면 대상 기기의 OS를 대략 추측할 수 있다. 예를 들어 TTL이 114라면 128에서 출발해 14홉을 거쳐 도착했다는 의미로, Windows 기기일 가능성이 높다.

아래는 ping 실행 결과의 예시다:

각 항목의 의미는 다음과 같다.

| 항목 | 설명 |
|------|------|
| `icmp_seq` | 패킷 순서 번호. 1부터 순서대로 증가한다. |
| `ttl` | Time To Live. 패킷이 거쳐갈 수 있는 최대 네트워크 홉 수. |
| `time` | 에코 패킷을 보내고 에코 응답을 받기까지 걸린 시간(ms). 낮을수록 응답이 빠르다. |
| `packets transmitted` | 전송한 패킷 수 |
| `received` | 수신한 패킷 수 |
| `packet loss` | 손실된 패킷 비율. 0%이면 모두 정상 수신. |
| `avg` | 평균 응답 시간 |

위 예시에서는 12개 패킷을 모두 수신했고(0% loss), 평균 응답 시간은 46.977ms다. 응답 시간이 일정하고 패킷 손실이 없으면 연결이 안정적이라는 의미다.

## ping이 실패하는 경우

ping 응답이 없다고 해서 무조건 서버가 꺼진 것은 아니다. 크게 두 가지 경우로 나뉜다.

| 원인 | 설명 |
|------|------|
| 서버 다운 | 대상 기기가 꺼져 있거나 네트워크에서 이탈한 상태 |
| ICMP 차단 | 방화벽이 ICMP 패킷을 차단하도록 설정된 상태 |

두 경우 모두 `Request timeout` 또는 `No route to host` 메시지가 출력되기 때문에 ping만으로는 구분하기 어렵다. 실제로 많은 서버(예: 구글, 클라우드 서비스)는 보안상의 이유로 ICMP를 차단하는 경우가 있어 ping이 실패하더라도 서비스 자체는 정상 동작 중일 수 있다.

## 마무리

ping은 네트워크를 배울 때 가장 먼저 접하게 되는 도구다. 단순해 보이지만 ICMP 에코 교환이라는 명확한 원리 위에서 동작하며, 연결 여부와 응답 시간이라는 핵심 정보를 빠르게 파악할 수 있다. 네트워크에 문제가 생겼을 때 ping을 먼저 실행해보는 습관을 들이면 원인을 좁혀가는 데 큰 도움이 된다.
