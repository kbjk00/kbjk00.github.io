## 시작하며

네트워크 안의 수많은 기기들은 서로를 어떻게 구별할까요? 이 글을 읽으면 IP 주소와 MAC 주소의 차이, 그리고 IPv4와 IPv6의 관계를 이해할 수 있습니다.

<br>

## 기기도 신원이 필요하다

사람이 다른 사람에게 편지를 보내려면 두 가지가 필요합니다.

<br>

**받는 사람의 집 주소**와 **받는 사람이 누구인지**입니다.

<br>

집 주소만 알면 어디로 보낼지는 알지만, 그 집에 누가 사는지는 확인할 수 없습니다. 반대로 이름만 알면 어디로 보내야 할지 모릅니다. 둘 다 있어야 정확하게 전달됩니다.

<br>

네트워크도 마찬가지입니다. 기기끼리 데이터를 주고받으려면 두 가지 식별자가 필요합니다.

<br>

- **IP 주소** — "어디에 있는가" (위치 식별자)
- **MAC 주소** — "어떤 기기인가" (하드웨어 식별자)

<br>

## IP 주소 — 변하는 위치 식별자

### IP 주소란?

**IP(Internet Protocol) 주소**는 네트워크에서 기기의 위치를 나타내는 논리적 식별자입니다.

<br>

주민등록상 주소처럼, 기기가 어느 네트워크에 연결되어 있느냐에 따라 달라집니다. 이사를 가면 주소가 바뀌듯, 기기가 다른 네트워크에 연결되면 IP 주소도 바뀔 수 있습니다.

<br>

IPv4 기준으로 IP 주소는 **4개의 옥텟(octet)을 점(.)으로 구분**한 형태입니다.

<br>

```text
192.168.1.77
```

<br>

각 숫자는 0~255 사이 값을 가집니다. 이 네 자리의 조합으로 네트워크상의 기기 위치를 나타냅니다.

<br>

한 가지 규칙이 있습니다. **같은 네트워크 안에서 동일한 IP 주소는 동시에 두 기기에 할당될 수 없습니다.** 같은 건물에 같은 호수의 방이 두 개일 수 없는 것과 같습니다.

<br>

### 사설 IP vs 공인 IP

IP 주소에는 두 가지 종류가 있습니다.

<br>

| 구분 | 역할 | 예시 |
|------|------|------|
| **사설 IP (Private IP)** | 같은 네트워크 내부에서 기기 간 통신에 사용 | 192.168.1.77, 192.168.1.74 |
| **공인 IP (Public IP)** | 인터넷에서 해당 네트워크를 식별하는 데 사용 | 86.157.52.21 |

<br>

사설 IP로 사용할 수 있는 대역은 국제 표준(RFC 1918)으로 정해져 있습니다.

<br>

| 대역 | 범위 | 주요 사용처 |
|------|------|------------|
| `10.0.0.0/8` | 10.0.0.0 ~ 10.255.255.255 | 대규모 기업 내부망 |
| `172.16.0.0/12` | 172.16.0.0 ~ 172.31.255.255 | 중간 규모 네트워크 |
| `192.168.0.0/16` | 192.168.0.0 ~ 192.168.255.255 | 가정용 공유기 |

<br>

이 범위에 속하지 않는 나머지 주소는 공인 IP 대역입니다. 공인 IP는 IANA(Internet Assigned Numbers Authority)가 전 세계적으로 관리하며, 각 국가·지역의 기관을 통해 ISP에 할당됩니다.

<br>

아파트 단지로 생각해 보면 쉽습니다. 단지 안에서는 동·호수(사설 IP)로 각 집을 구분합니다. 그런데 외부에서 택배를 보낼 때는 단지 전체의 도로명 주소(공인 IP)로 보냅니다. 단지 안의 여러 집이 하나의 외부 주소를 공유하는 구조입니다.

<br>

공인 IP는 **ISP(인터넷 서비스 제공업체)**가 할당합니다. 매달 내는 인터넷 요금이 이 서비스의 대가이기도 합니다.

<br>

### IPv4와 IPv6 — 주소가 부족해졌다

**IPv4(Internet Protocol version 4)**는 현재 가장 널리 쓰이는 인터넷 주소 체계 표준으로, 위에서 설명한 32비트 점 표기 방식이 바로 IPv4입니다.

<br>

IPv4는 2³² = 약 **43억 개**의 주소를 만들 수 있습니다. 처음 인터넷이 설계될 때만 해도 충분해 보였지만, 스마트폰·IoT 기기·스마트 가전 등이 폭발적으로 늘어나면서 주소가 빠르게 고갈되기 시작했습니다.

<br>

이 문제를 해결하기 위해 등장한 것이 **IPv6**입니다.

<br>

| 항목 | IPv4 | IPv6 |
|------|------|------|
| 주소 수 | 2³² ≈ 43억 | 2¹²⁸ ≈ 340조 이상 |
| 표기 형식 | `192.168.1.1` | `2001:0db8:85a3::8a2e:0370:7334` |
| 효율성 | 상대적으로 낮음 | 개선된 방법론 적용 |

<br>

IPv6는 128비트 주소 체계를 사용해 사실상 무한에 가까운 주소를 제공합니다. 표기가 복잡해 보이지만, 그만큼 훨씬 많은 기기를 수용할 수 있습니다.

<br>

### IP 스푸핑

IP 주소는 변경이 가능하다는 특성 때문에 악용될 여지가 있습니다. 패킷의 출발지 IP 주소를 실제와 다른 값으로 위조하는 것을 **IP 스푸핑(IP Spoofing)**이라고 합니다.

<br>

공격자는 이 방법으로 자신의 IP 주소를 숨기거나, 신뢰할 수 있는 기기인 것처럼 위장해 보안 필터를 우회할 수 있습니다. DDoS 공격에서도 출처를 추적하기 어렵게 만들기 위해 자주 활용됩니다.

<br>

## MAC 주소 — 변하지 않는 하드웨어 식별자

### MAC 주소란?

**MAC(Media Access Control) 주소**는 네트워크 인터페이스 카드(NIC)에 제조 시점에 새겨지는 고유 식별자입니다.

<br>

주민등록번호와 비슷합니다. 태어날 때(여기서는 공장 출고 시) 부여되고, 이후에는 바뀌지 않습니다. 기기가 어느 네트워크에 연결되든, IP 주소가 달라지든 MAC 주소는 그대로입니다.

<br>

MAC 주소는 **12자리 16진수**를 콜론(:)으로 2자리씩 구분한 형태입니다.

<br>

```text
a4:c3:f0:85:ac:2d
```

<br>

- **앞 6자리** (`a4:c3:f0`): 제조사 식별 코드
- **뒤 6자리** (`85:ac:2d`): 해당 제조사가 부여한 고유 번호

<br>

즉, MAC 주소만 봐도 어느 회사가 만든 네트워크 장치인지 알 수 있습니다.

<br>

### MAC 스푸핑

MAC 주소는 고정되어 있지만, 소프트웨어 수준에서 다른 값으로 위장하는 것이 가능합니다. 이를 **MAC 스푸핑(MAC Spoofing)**이라고 합니다.

<br>

MAC 주소만으로 신뢰 여부를 판단하는 보안 설계는 이 방법으로 우회될 수 있습니다. 따라서 MAC 기반 접근 제어는 단독으로 사용하기보다 다른 인증 수단과 함께 적용하는 것이 안전합니다.

<br>

### MAC 스푸핑과 IP 스푸핑 비교

| 항목 | MAC 스푸핑 | IP 스푸핑 |
|------|-----------|----------|
| 위조 대상 | MAC 주소 (하드웨어 식별자) | IP 주소 (위치 식별자) |
| 주요 범위 | 같은 네트워크 내부 | 인터넷을 통한 외부 공격 포함 |
| 주요 목적 | 접근 제어 우회 | 신원 은닉, 보안 필터 우회, DDoS |

<br>

## 정리

| 항목 | IP 주소 | MAC 주소 |
|------|---------|---------|
| 역할 | 네트워크상 위치 식별 | 하드웨어(기기) 식별 |
| 변경 가능 여부 | 가능 (네트워크 이동 시 변경) | 고정 (제조 시 할당) |
| 할당 주체 | 네트워크/ISP | 제조사 |
| 형식 (예시) | `192.168.1.77` (IPv4) | `a4:c3:f0:85:ac:2d` |
| 비고 | IPv4 고갈 → IPv6로 전환 중 | 앞 6자리: 제조사 / 뒤 6자리: 고유 번호 |

<br>

## 마치며

IP 주소는 기기가 지금 어디에 있는지를, MAC 주소는 그 기기가 무엇인지를 나타냅니다. 네트워크 통신은 이 두 식별자가 함께 작동하면서 이루어집니다.
