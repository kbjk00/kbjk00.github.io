## 시작하며

1주차에 팀장으로 선정되면서 원래 계획했던 주차별 내용을 수정하여 달라진 부분이 많았습니다. 

이번 2주차에는 Git diff 실습과 bWAPP 실습을 진행합니다.

<br>

이 글은 Git diff 실습을 위해 직접 만든 문제를 풀어보는 글입니다.

`git diff`를 활용해 커밋 간 차이를 추출하고, 패치 파일로 파일을 복원하는 과정을 다룹니다.

<br>

## lv1.py

lv1.py는 git diff로 패치 파일을 만든 다음 패치를 하여 Correct!가 출력되게 하는 플래그를 찾는 문제입니다.

먼저 로그를 확인하여 플래그가 어디있는지 찾아보겠습니다.

<br>

```bash
git log --oneline
```

<br>

그럼 다음과 같은 내용이 출력됩니다.

![git log --oneline 결과](/assets/img/2026-03-25-취약점-분석-및-서비스-개선-2주차---Git-diff-실습해보기/lv1-git-log.png)

log의 순서는 다음과 같습니다.

* 왼쪽 : 커밋 해시
* 오른쪽 : 커밋 내용

<br>

커밋 내용을 보면 `Fix: I delete a flag`가 있습니다.

즉, 플래그를 제거한다는 말이고 이 부분과 이전 부분의 차이를 확인해보면 그곳에 플래그가 있을 것입니다.

<br>

`git diff` 명령어를 사용하여 둘의 차이를 확인하기 위해 `fix.patch` 라는 파일을 만들겠습니다.

`git diff`는 **구버전 커밋 → 신버전 커밋** 순서로 입력해야 합니다. 즉, 플래그가 있던 커밋을 먼저, 플래그를 제거한 커밋을 나중에 씁니다.

<br>

```bash
git diff <구버전 커밋 해시> <신버전 커밋 해시> > fix.patch
```

<br>

만약 리눅스 환경이 아닌 Powershell이라면 다른 명령어를 사용해야 합니다.

 ```powershell
 git diff [구버전 커밋 해시] [신버전 커밋 해시] | Out-File -FilePath fix.patch -Encoding utf8
 ```

<br>

이제 fix.patch가 생성되었습니다.

먼저 이 파일을 `cat`으로 읽어보겠습니다.

<br>

```bash
cat fix.patch
```

<br>

![fix.patch cat 결과](/assets/img/2026-03-25-취약점-분석-및-서비스-개선-2주차---Git-diff-실습해보기/lv1-fix-patch-cat.png)

<br>

![fix.patch 내용](/assets/img/2026-03-25-취약점-분석-및-서비스-개선-2주차---Git-diff-실습해보기/lv1-fix-patch-content.png)

<br>

flag에 `Pay1oad{I_think_you_know_git_diff!}`가 있었고 이 내용이 DELETE로 바뀌었음을 알 수 있습니다.

그럼 이제 복원을 해서 Correct!가 나오는지 알아보겠습니다.

`-R` 옵션은 reverse(역방향)로, diff의 방향을 반대로 적용합니다. 즉, 삭제된 내용을 다시 추가하여 이전 버전으로 복원합니다.

<br>

```bash
patch -R lv1.py -i fix.patch
```

<br>

이제 패치가 되었으니 파일을 실행하겠습니다.

<br>

![lv1.py Correct! 실행 결과](/assets/img/2026-03-25-취약점-분석-및-서비스-개선-2주차---Git-diff-실습해보기/lv1-correct.png)

<br>

Correct!가 나오기 때문에 이 플래그가 올바른 플래그임을 알 수 있습니다.

<br>

## lv2.py

이번 문제는 lv1.py와 똑같이 플래그를 찾는 문제이지만 커밋의 수가 더 많습니다. 이 중 플래그가 나오게 하는 커밋을 찾아야 합니다.

<br>

똑같이 커밋을 확인해보겠습니다.

<br>

```bash
git log --oneline
```

<br>

출력 결과는 다음과 같습니다.

![lv2 git log --oneline 결과](/assets/img/2026-03-25-취약점-분석-및-서비스-개선-2주차---Git-diff-실습해보기/lv2-git-log.png)

커밋으로 순서를 살펴보면 다음과 같습니다. (git log는 최신 커밋이 위에 출력되므로, 아래가 오래된 순입니다.)

1. lv2.py와 README 추가 ← 가장 오래된 커밋
2. input_info 추가
3. input_info 제거
4. 코드 최적화 ← 가장 최신 커밋

<br>

`input_info`를 추가하고 제거했으니 이 내용이 무엇인지 찾아보도록 하겠습니다.

2번을 사용하여 `git diff`를 하겠습니다.

<br>

```bash
git diff f66371e 60875d8 > fix.patch
```

<br>

`cat`을 사용하여 패치 파일을 보니 다음과 같이 나옵니다.

![lv2 fix.patch 내용](/assets/img/2026-03-25-취약점-분석-및-서비스-개선-2주차---Git-diff-실습해보기/lv2-fix-patch-content.png)

<br>

`Pay1oad{g1t_l0g_1s_k3y!}`가 `input_info`에 있었고 `input_info`가 삭제되며 플래그가 사라진 것입니다.

<br>

파일을 이전 버전으로 복원하여 Correct!가 나오는지 확인해보겠습니다.

<br>

```bash
patch -R lv2.py -i fix.patch
```

<br>

![lv2.py Correct! 실행 결과](/assets/img/2026-03-25-취약점-분석-및-서비스-개선-2주차---Git-diff-실습해보기/lv2-correct.png)

<br>

Correct!가 나오므로 이 값이 올바른 플래그임을 알 수 있습니다.

<br>

## 정리

| 명령어 | 역할 |
|--------|------|
| `git log --oneline` | 커밋 해시와 메시지를 한 줄로 확인 |
| `git diff <해시1> <해시2> > fix.patch` | 두 커밋 간 차이를 패치 파일로 저장 |
| `patch -R <파일> -i <패치 파일>` | 패치 파일을 역방향 적용하여 이전 버전으로 복원 |

<br>

## 마치며

`git log`로 의심스러운 커밋을 찾고, `git diff`로 차이를 추출한 뒤 `patch -R`로 복원하는 흐름을 익혔습니다.
