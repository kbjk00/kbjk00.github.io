## 시작하며

지난 글에서 Patch Diff로 코드 변경사항을 읽는 법을 익혔습니다. 이번 글에서는 실제로 취약점을 분석할 때 **무엇을 봐야 하는지**, **어떻게 분석하는지**를 다룹니다.

<br>

1day 취약점 분석의 출발점은 CVE입니다. CVE를 찾아서 열어보면 여러 항목이 나오는데, 처음에는 어디서부터 읽어야 할지 막막합니다. 이 글에서는 분석 대상 리스트와 각 항목을 해석하는 방법을 체계적으로 정리합니다.

<br>

## 취약점 분석이란?

**1day 취약점 분석**이란 이미 공개된 취약점(CVE)을 분석해 어떻게 동작하는지, 어떤 조건에서 악용될 수 있는지 이해하는 과정입니다.

<br>

분석의 목적은 두 가지입니다.

- **공격자 관점**: 취약점이 실제로 악용 가능한지, 조건이 무엇인지 파악
- **방어자 관점**: 패치 적용 우선순위 결정, 영향받는 시스템 파악

<br>

취약점 하나를 분석하려면 CVE, CWE, CVSS, NVD 네 가지 시스템을 알아야 합니다. 각각의 역할이 다르고, 서로 연결되어 있습니다.

<br>

## CVE · CWE · CVSS · NVD — 네 시스템의 관계

먼저 네 시스템이 어떻게 연결되어 있는지 이해하는 것이 중요합니다.

<br>

```text
CWE (약점 유형 분류)
 └─ CVE (특정 취약점 사례) ──→ NVD (CVE + CVSS + CWE 통합 DB)
         └─ CVSS (심각도 점수)
```

<br>

| 시스템 | 역할 | 예시 |
|--------|------|------|
| **CVE** | 개별 취약점의 고유 식별자 | CVE-2024-12345 |
| **CWE** | 취약점의 근본 원인·유형 분류 | CWE-79 (XSS) |
| **CVSS** | 취약점의 심각도 점수 (0~10) | 8.8 HIGH |
| **NVD** | CVE + CVSS + CWE를 통합한 미국 정부 DB | nvd.nist.gov |

<br>

- **CVE**는 "이 취약점"이 무엇인지를 가리키는 이름표입니다.
- **CWE**는 그 취약점이 어떤 유형의 약점에서 비롯됐는지를 분류합니다.
- **CVSS**는 그 취약점이 얼마나 위험한지를 점수로 표현합니다.
- **NVD**는 이 세 가지 정보를 한 곳에서 조회할 수 있는 데이터베이스입니다.

<br>

## 분석 대상 리스트

CVE 항목을 열었을 때 봐야 할 항목들입니다. NVD(nvd.nist.gov)에서 CVE ID로 검색하면 아래 항목들을 확인할 수 있습니다.

<br>

### 1. CVE ID

```text
CVE-[연도]-[번호]
예: CVE-2024-12345
```

<br>

취약점의 고유 식별자입니다. 연도와 일련번호로 구성됩니다. 같은 취약점을 다른 사람과 논의하거나 검색할 때 이 ID를 기준으로 합니다.

<br>

### 2. 설명 (Description)

취약점이 무엇인지, 어떤 제품/버전에 존재하는지, 어떤 영향을 미치는지를 서술합니다.

<br>

표준 작성 형식은 다음과 같습니다.

```text
[제품명] [버전 범위]의 [컴포넌트]에서 [취약점 유형]으로 인해
[공격자]가 [공격 벡터]를 통해 [영향]을 줄 수 있다.
```

<br>

설명에서 확인해야 할 것:
- 어떤 제품/컴포넌트에 존재하는가
- 공격자가 무엇을 할 수 있는가 (원격 코드 실행, 정보 노출, 서비스 거부 등)
- 공격에 필요한 조건이 있는가 (인증 필요 여부 등)

<br>

### 3. CWE (약점 유형)

취약점의 근본 원인 유형입니다. "이 취약점은 왜 발생했는가"를 분류합니다.

<br>

| CWE ID | 이름 | 설명 |
|--------|------|------|
| CWE-79 | XSS | 입력값이 HTML에 그대로 출력됨 |
| CWE-89 | SQL Injection | 입력값이 SQL 쿼리에 그대로 삽입됨 |
| CWE-787 | Out-of-bounds Write | 배열/버퍼 범위를 벗어난 쓰기 |
| CWE-22 | Path Traversal | 파일 경로 조작으로 허가되지 않은 파일 접근 |
| CWE-416 | Use After Free | 해제된 메모리를 재사용 |

<br>

CWE를 확인하면 취약점이 어떤 클래스의 버그인지 파악할 수 있습니다. CWE Top 25(cwe.mitre.org)는 가장 위험한 약점 25개를 정리한 목록으로, 우선순위 판단에 활용합니다.

<br>

### 4. CVSS 점수 및 벡터

이 글은 CVSS v4.0 기준으로 설명합니다. NVD에서는 v3.1 점수도 함께 표시되는 경우가 있습니다.

<br>

취약점의 심각도를 0.0~10.0 점수로 표현합니다. 점수만 보지 말고 **벡터**를 함께 읽어야 합니다.

<br>

**심각도 등급:**

| 등급 | 점수 범위 |
|------|---------|
| None | 0.0 |
| Low | 0.1 – 3.9 |
| Medium | 4.0 – 6.9 |
| High | 7.0 – 8.9 |
| Critical | 9.0 – 10.0 |

<br>

**벡터 스트링 예시:**

```text
CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N
```

<br>

각 항목의 의미는 다음 섹션에서 설명합니다.

<br>

### 5. 영향받는 버전 (Affected Versions)

어떤 제품의 어떤 버전이 취약한지 명시합니다. 패치 적용 여부 판단의 기준이 됩니다.

<br>

확인해야 할 것:
- 현재 운영 중인 버전이 포함되는가
- 수정 버전(Fixed Version)은 무엇인가

<br>

### 6. 참조 링크 (References)

패치 커밋, 보안 공지, PoC(Proof of Concept) 코드, 분석 블로그 등의 링크입니다.

<br>

참조 링크에서 확인할 것:
- **패치 커밋**: 실제로 어떤 코드가 수정됐는지 (Patch Diff 분석 대상)
- **보안 공지**: 벤더의 공식 권고사항
- **PoC**: 취약점이 실제로 악용되는 방식 예시

<br>

## 분석 방법 — CVSS 벡터 읽기

CVSS 점수 뒤에 붙는 벡터는 취약점의 특성을 인코딩한 문자열입니다. 각 항목을 읽으면 공격이 어떤 조건에서 가능한지 파악할 수 있습니다.

<br>

### 공격 가능성 항목

| 항목 | 약어 | 값 | 의미 |
|------|------|----|------|
| Attack Vector | AV | N (Network) | 원격에서 네트워크를 통해 공격 가능 |
| | | A (Adjacent) | 같은 네트워크 내에서만 공격 가능 |
| | | L (Local) | 로컬 접근(셸 등) 필요 |
| | | P (Physical) | 물리적 접근 필요 |
| Attack Complexity | AC | L (Low) | 특별한 조건 없이 공격 가능 |
| | | H (High) | 공격에 특수한 조건 필요 |
| Privileges Required | PR | N (None) | 인증 불필요 |
| | | L (Low) | 일반 사용자 권한으로 공격 가능 |
| | | H (High) | 관리자 권한 필요 |
| User Interaction | UI | N (None) | 피해자의 행동 불필요 |
| | | P (Passive) | 피해자가 단순히 페이지를 방문하는 것만으로 발동 |
| | | A (Active) | 피해자가 특정 행동을 해야 함 |

<br>

### 영향 항목

공격이 성공했을 때 어떤 피해가 발생하는지를 나타냅니다.

<br>

| 항목 | 약어 | 의미 |
|------|------|------|
| Confidentiality | VC/SC | 기밀성 — 데이터 노출 여부 |
| Integrity | VI/SI | 무결성 — 데이터 변조 여부 |
| Availability | VA/SA | 가용성 — 서비스 중단 여부 |

<br>

각 항목의 값: H(High), L(Low), N(None)

<br>

**읽기 예시:**

```text
CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N
```

→ 네트워크를 통해(AV:N), 특별한 조건 없이(AC:L), 추가 요구사항 없이(AT:N), 인증 없이(PR:N), 피해자 행동 없이(UI:N) 공격 가능.
→ 공격 성공 시 취약 시스템의 기밀성·무결성·가용성 모두 High 수준의 피해(VC:H/VI:H/VA:H).
→ 이런 벡터는 Critical 점수에 가깝고 즉각 패치 우선순위가 높습니다.

<br>

## NVD에서 CVE 조회하는 법

NVD(nvd.nist.gov)는 CVE + CWE + CVSS 정보를 통합해서 제공합니다.

<br>

**조회 방법:**
1. nvd.nist.gov 접속
2. 검색창에 CVE ID 입력 (예: `CVE-2024-12345`)
3. 항목 클릭 → 설명, CVSS 벡터, CWE, 영향받는 버전, 참조 링크 확인

<br>

NVD는 CVE 발행 후 CVSS 점수와 CWE 분류를 추가로 분석해서 등록합니다. CVE만 있는 항목보다 NVD에 등록된 항목이 더 많은 정보를 제공합니다.

<br>

## 정리

| 분석 대상 | 확인 내용 |
|-----------|-----------|
| CVE ID | 취약점 식별자, 연도·번호 구조 |
| 설명 | 제품/버전, 공격자가 할 수 있는 것, 공격 조건 |
| CWE | 근본 원인 유형 (XSS, SQLi, OOB 등) |
| CVSS 점수 | 심각도 등급 (None/Low/Medium/High/Critical) |
| CVSS 벡터 | 공격 경로(AV), 조건(AC), 권한(PR), 사용자 행동(UI), 영향(C/I/A) |
| 영향받는 버전 | 취약한 버전 범위, 수정 버전 |
| 참조 링크 | 패치 커밋, 보안 공지, PoC |

<br>

## 마치며

CVE 항목을 처음 열었을 때 막막했다면, 이 분석 대상 리스트를 체크리스트처럼 사용하면 됩니다. CVSS 벡터를 읽을 수 있으면 점수 숫자만 볼 때보다 훨씬 정확하게 위험도를 판단할 수 있습니다.
