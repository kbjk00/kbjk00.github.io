## 시작하며

네트워크 기초를 배우다 보면 'LAN'이라는 단어를 자주 마주칩니다. 가정이나 학교 같은 제한된 공간에서 기기들이 어떻게 연결되고 통신하는지가 바로 LAN의 핵심입니다. 이 글에서는 LAN이 무엇인지, 네트워크를 설계하는 방식(토폴로지), 그리고 LAN에서 통신이 이루어지는 데 핵심적인 역할을 하는 ARP와 DHCP를 다룹니다.

## LAN이란

**LAN(Local Area Network, 근거리 통신망)**은 가정, 사무실, 학교처럼 물리적으로 제한된 범위 안에서 기기들이 서로 연결된 네트워크입니다. 인터넷 전체가 아닌, 그 이전 단계인 '내 주변 기기들끼리의 연결'이 LAN입니다.

LAN 안에서 기기들은 스위치나 라우터 같은 네트워크 장비를 통해 연결됩니다. 이때 기기들이 어떤 구조로 연결되는지를 **토폴로지(Topology)**라고 합니다.

## LAN 토폴로지

토폴로지는 네트워크의 설계 형태, 즉 기기들이 어떻게 연결되어 있는지를 나타냅니다. 대표적인 세 가지 토폴로지를 살펴보겠습니다.

### 스타 토폴로지 (Star Topology)

스위치나 허브 같은 **중앙 장치**에 모든 기기가 개별적으로 연결되는 구조입니다. 오늘날 가장 널리 사용되는 방식입니다.

| 장점 | 단점 |
|------|------|
| 확장성이 뛰어남 (기기 추가 용이) | 케이블과 전용 장비 비용이 더 듦 |
| 한 기기에 문제가 생겨도 다른 기기에 영향 없음 | 중앙 장치가 고장나면 모든 통신 중단 |

### 버스 토폴로지 (Bus Topology)

모든 기기가 **하나의 백본 케이블(backbone cable)**에 연결된 구조입니다. 나뭇가지에 잎이 달린 모습을 떠올리면 됩니다.

| 장점 | 단점 |
|------|------|
| 구축 비용이 저렴 | 모든 기기가 같은 케이블을 공유해 병목 현상 발생 |
| 구조가 단순 | 백본 케이블이 단일 장애 지점 (케이블 끊기면 전체 마비) |
|  | 문제 기기 파악이 어려움 |

### 링 토폴로지 (Ring Topology)

기기들이 **루프 형태로 직접 연결**되는 구조입니다. 데이터는 루프를 따라 한 방향으로만 이동하며, 목적지에 도달할 때까지 중간 기기들이 데이터를 중계합니다.

| 장점 | 단점 |
|------|------|
| 데이터가 단방향으로만 이동해 장애 위치 파악이 비교적 쉬움 | 목적지까지 여러 기기를 거쳐야 해 효율이 낮음 |
| 동시 트래픽이 분산되어 버스 토폴로지보다 병목이 적음 | 기기 하나가 고장나거나 케이블이 끊기면 전체 네트워크 중단 |

## 스위치와 라우터

LAN을 구성하는 핵심 장비들입니다. 스위치는 허브의 발전된 형태로, 허브와 달리 목적지 포트에만 데이터를 전송합니다.

| 장치 | 역할 | 특징 |
|------|------|------|
| 허브(Hub) | LAN 내 기기 연결 | 모든 포트에 데이터 브로드캐스트 |
| 스위치(Switch) | LAN 내 기기 연결 | 목적지 포트에만 데이터 전송 (효율적) |
| 라우터(Router) | 네트워크 간 연결 | 서로 다른 네트워크를 이어주는 장치 |

스위치와 라우터를 함께 연결하면 데이터가 이동할 수 있는 경로가 여러 개 생겨 하나의 경로가 끊겨도 다른 경로를 사용할 수 있습니다.

## ARP — IP 주소로 MAC 주소 찾기

LAN 안에서 기기들은 **IP 주소**와 **MAC 주소**라는 두 가지 식별자를 갖습니다. 데이터를 전송하려면 목적지 기기의 MAC 주소를 알아야 하는데, **ARP(Address Resolution Protocol)**가 이 문제를 해결합니다.

ARP는 IP 주소를 MAC 주소로 변환하는 프로토콜입니다.

### 동작 과정

1. **ARP 요청(ARP Request)**: "이 IP 주소를 가진 기기의 MAC 주소는 무엇인가?"라는 메시지를 네트워크 전체에 브로드캐스트합니다.
2. **ARP 응답(ARP Reply)**: 해당 IP 주소를 가진 기기만 자신의 MAC 주소를 담아 응답합니다.
3. **ARP 캐시 저장**: 요청한 기기는 이 IP-MAC 매핑을 **ARP 캐시**에 저장해 이후에 같은 기기와 통신할 때 재사용합니다.

ARP 캐시 덕분에 매번 브로드캐스트를 보낼 필요 없이 빠르게 통신할 수 있습니다.

## DHCP — IP 주소 자동 할당

기기를 네트워크에 연결할 때마다 IP 주소를 수동으로 설정하는 건 번거롭습니다. **DHCP(Dynamic Host Configuration Protocol)**는 이 과정을 자동화해줍니다.

### 동작 과정 (4단계)

| 단계 | 방향 | 설명 |
|------|------|------|
| **DHCP Discover** | 기기 → 네트워크 | "DHCP 서버 있나요?" 브로드캐스트 |
| **DHCP Offer** | DHCP 서버 → 기기 | "이 IP 주소 쓸 수 있어요" 제안 |
| **DHCP Request** | 기기 → DHCP 서버 | "그 IP 주소 사용할게요" 확인 요청 |
| **DHCP ACK** | DHCP 서버 → 기기 | "확인, 사용하세요" 최종 승인 |

이 4단계를 거치면 기기는 별도 설정 없이 자동으로 IP 주소를 할당받고 네트워크에 참여할 수 있습니다. 단, 할당된 IP 주소에는 **임대 기간(Lease Time)**이 있어, 기간이 만료되면 갱신 요청을 통해 계속 사용하거나 새 주소를 받게 됩니다.

## 정리

| 개념 | 역할 |
|------|------|
| LAN | 제한된 공간 내 기기들의 네트워크 |
| 스타 토폴로지 | 중앙 장치에 모든 기기 개별 연결. 현재 가장 많이 사용 |
| 버스 토폴로지 | 단일 케이블에 모든 기기 연결. 저렴하지만 단일 장애 지점 존재 |
| 링 토폴로지 | 루프 형태 연결. 단방향 데이터 흐름 |
| 스위치 | LAN 내 기기 연결, 목적지에만 데이터 전송 |
| 라우터 | 네트워크 간 연결 및 데이터 전달 |
| ARP | IP 주소 → MAC 주소 변환 프로토콜 |
| DHCP | IP 주소 자동 할당 프로토콜 (4단계: Discover → Offer → Request → ACK) |

## 마치며

LAN은 인터넷 이전의 가장 작은 네트워크 단위입니다. 기기들이 어떤 구조로 연결되는지(토폴로지), LAN 안에서 기기를 어떻게 찾는지(ARP), IP 주소를 어떻게 자동으로 받는지(DHCP)를 이해하면 네트워크 통신의 기초가 잡힙니다. 특히 ARP는 LAN 내에서의 스푸핑 공격(ARP Spoofing)의 기반이 되기 때문에, 이 동작 원리를 이해하는 것은 네트워크 보안의 첫걸음이기도 합니다.
