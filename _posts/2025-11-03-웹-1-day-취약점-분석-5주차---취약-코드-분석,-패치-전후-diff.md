## 취약 코드 분석

Spring4Shell 취약점이 발생하는 원인은 ClassLoader 와 JDK 9++ 이다.

이에 대해 말하기 전에 데이터 바인딩에 대해서 알아보자.

데이터 바인딩이란 두 개의 데이터를 함께 연결하고 동기화 상태를 유지하는 것을 말한다.

<br>

Spring Framework 에서는 데이터 바인딩을 수행할 때 외부에서 수정되는 것을 방지하기 위해

조건문을 통해 값을 검증하는 코드가 존재한다.

하지만 JDK 9 버전부터 모듈 클래스가 도입되면서 ClassLoader 객체를 외부에서 수정할 수 있게 되었다.

<br>

ClassLoader 는 클래스가 요청될 때 \*.class 바이트코드를 읽어 객체를 생성하는 역할을 하는 JVM 구성요소이다.

다시 말해서, ClassLoader 를 외부에서 수정한다는 것은 내부 객체를 변조하는 것이 가능하다는 말이다.

이러한 점이 Spring4Shell 취약점으로 이어졌다.

<br>

Spring Framework 5.3.17 버전의 소스 코드를 살펴보면 다음과 같은 코드가 있다.

```
PropertyDescriptor[] pds = this.beanInfo.getPropertyDescriptors();
			for (PropertyDescriptor pd : pds) {
				if (Class.class == beanClass &&
						("classLoader".equals(pd.getName()) ||  "protectionDomain".equals(pd.getName()))) {
					// Ignore Class.getClassLoader() and getProtectionDomain() methods - nobody needs to bind to those
					continue;
				}
				if (logger.isTraceEnabled()) {
					logger.trace("Found bean property '" + pd.getName() + "'" +
							(pd.getPropertyType() != null ? " of type [" + pd.getPropertyType().getName() + "]" : "") +
							(pd.getPropertyEditorClass() != null ?
									"; editor [" + pd.getPropertyEditorClass().getName() + "]" : ""));
				}
				pd = buildGenericTypeAwarePropertyDescriptor(beanClass, pd);
				this.propertyDescriptors.put(pd.getName(), pd);
				Method readMethod = pd.getReadMethod();
				if (readMethod != null) {
					readMethodNames.add(readMethod.getName());
				}
			}
```

이 코드 중 조건문을 살펴보겠다.

```
if (Class.class == beanClass &&
    ("classLoader".equals(pd.getName()) || "protectionDomain".equals(pd.getName()))) {
    // Ignore Class.getClassLoader() and getProtectionDomain() methods - nobody needs to bind to those
    continue;
}
```

이 조건문은 Class 객체의 내부 구조를 조작하는 것을 막기 위해

classLoader, protectionDomain 에 대한 데이터 바인딩을 무시하고 건너뛰기 위해 존재했다.

하지만 JDK 9부터 모듈이 도입되었는데 모듈 속성에 대해서는 전혀 차단을 하지 않는 문제가 발생하였다.

<br>

따라서 모듈을 사용하여 ClassLoader 에 접근하는 것이 가능하였다.

## 패치 전후 diff

그렇다면 패치가 된 후에는 무엇이 달려졌을까?

한 번 Spring Framework 5.3.18 을 살펴보자.

```
PropertyDescriptor[] pds = this.beanInfo.getPropertyDescriptors();
			for (PropertyDescriptor pd : pds) {
				if (Class.class == beanClass && (!"name".equals(pd.getName()) && !pd.getName().endsWith("Name"))) {
					// Only allow all name variants of Class properties
					continue;
				}
				if (pd.getPropertyType() != null && (ClassLoader.class.isAssignableFrom(pd.getPropertyType())
						|| ProtectionDomain.class.isAssignableFrom(pd.getPropertyType()))) {
					// Ignore ClassLoader and ProtectionDomain types - nobody needs to bind to those
					continue;
				}
				if (logger.isTraceEnabled()) {
					logger.trace("Found bean property '" + pd.getName() + "'" +
							(pd.getPropertyType() != null ? " of type [" + pd.getPropertyType().getName() + "]" : "") +
							(pd.getPropertyEditorClass() != null ?
									"; editor [" + pd.getPropertyEditorClass().getName() + "]" : ""));
				}
				pd = buildGenericTypeAwarePropertyDescriptor(beanClass, pd);
				this.propertyDescriptors.put(pd.getName(), pd);
				Method readMethod = pd.getReadMethod();
				if (readMethod != null) {
					readMethodNames.add(readMethod.getName());
				}
			}
```

다음은 Spring Framework 5.3.18 의 소스코드이다.

기존 5.3.17 과 다른 부분은 다음과 같다.

```
if (Class.class == beanClass && (!"name".equals(pd.getName()) && !pd.getName().endsWith("Name"))) {
					// Only allow all name variants of Class properties
					continue;
				}
				if (pd.getPropertyType() != null && (ClassLoader.class.isAssignableFrom(pd.getPropertyType())
						|| ProtectionDomain.class.isAssignableFrom(pd.getPropertyType()))) {
					// Ignore ClassLoader and ProtectionDomain types - nobody needs to bind to those
					continue;
				}
```

기존과 다르게 클래스 속성의 이름 변수만 허용하도록 패치가 되었다.

또한 ClassLoader, ProtectionDomain 변조를 막기 위한 두 번째 조건문이 추가되었다.
